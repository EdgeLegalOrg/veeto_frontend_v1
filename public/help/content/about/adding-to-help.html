Adding to the help

How to add a page, a section or a whole book. The help is plain files, so there is nothing to build or install.

How the help is put together

  • The help lives in the application's public/help folder and is served at /help/.
  • content/nav.json lists the books, their sections and their pages. It makes the menu on the left, the previous and next links, and the search.
  • Each page is one HTML file in content/. It holds only the page's content, with no <html> or <body> around it.
  • The address of a page is #/<book>/<slug>, for example #/admin/roles.

To add a page

  1. Create the file, for example content/app/opening-a-matter.html.
  2. Start it with one <h1> for the title, then an optional <p class="lead"> that sums it up.
  3. Use <h2> for each main heading. These make the "On this page" list on the right.
  4. Add a line for it in nav.json, in the section it belongs to: 
    { "slug": "opening-a-matter", "title": "Opening a matter", "file": "content/app/opening-a-matter.html" }
  5. Open /help/#/app/opening-a-matter to check it. The menu, the pager and the search include it straight away.

The order in nav.json is the order in the menu and the order of the previous and next links.

To add a section

In the book's sections list, add an object with a title and a list of pages. A section with an empty title shows its pages with no heading.

To add a book

  1. Add an object to books with an id (used in addresses), a title, a status and its sections.
  2. Link to it from content/home.html if it should appear on the home page.

A book's status can be published or planned. A planned book is shown in the menu with a "to be written" label. Change it to published when the book is ready.

Writing the pages

  • Links between pages: <a href="#/admin/roles">Roles</a>. Always start with #/.
  • Steps: use <ol class="steps">.
  • Call-outs: <div class="note"><p>…</p></div> for a hint and class="warning" for something that can cause harm.
  • Pictures: put the file in img/ and refer to it with a relative path, for example <img src="img/matter-summary.png" alt="The Matter Summary tab">. Always give it an alt text.
  • Wording: use the names on the screen exactly, in bold, so people can find them.
  • Accuracy: describe only what the application does. If something is not settled, leave it out rather than guess.

Checking your changes

Serve the folder with any static web server and open it in a browser. Do not open the file directly from disk (a file:// address): the page loads its content with the browser's fetch, which a browser blocks for local files.

cd public/help
python -m http.server 8080

Then open http://localhost:8080/. Check that every link works, and that searching for a word from your page finds it.

How it is published

  • The help is part of the application's front end. Anything in public/help is copied into the build and served at /help/.
  • The web server must serve files that exist, such as /help/index.html, before it falls back to the application's own page. Files that exist are normally served as they are. The address /help (without the closing slash) must be redirected to /help/ so the page can find its style and scripts; the _redirects file has a rule for this on hosts that read it, and other web servers need the equivalent.
  • Nothing needs to be installed, and no database or back end is involved.

The help is public: anyone who knows the address can read it. Do not put anything confidential in a page, such as real names, addresses, secrets or customer data. Use made-up examples.
